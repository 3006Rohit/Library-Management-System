# Member engagement

All member-scoped, idempotent, and keyed on the session token. Storage is the private ledger `Library_Scan_Transaction__c` (see [objects README](../../../force-app/main/default/objects/README.md)) unless noted.

| Feature                 | Service (API)                                                                                                                                           | UI                                         | Rules                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reading list**        | `LibraryMemberEngagementService` — `getAll`, `save`, `remove`                                                                                           | `libraryMemberShell` (Reading Lists)       | States: Want to Read, Currently Reading, Completed, Abandoned; private notes; optional 1–5 rating; notify-when-available; one entry per member/book; only owner can remove. Target model: `Member_Book_Engagement__c`.                                |
| **Author follows**      | `LibraryMemberAuthorFollowService` — `getAll`, `follow`, `unfollow`                                                                                     | shell ("Authors I Follow", book details)   | Idempotent; never exposes other members' follows.                                                                                                                                                                                                     |
| **Reviews**             | `LibraryMemberReviewService` — `submit`, `getMine`, `getPublished`, `getPending`, `moderate`                                                            | shell + `libraryLibrarianReviewModeration` | 1–5 rating + short text; starts **Pending**; only librarian-approved (**Published**) reviews are public; moderation needs catalog permission.                                                                                                         |
| **Reading challenges**  | `LibraryChallengeService` — `create`, `getAvailable`, `enroll`, `leave`, `syncAchievements`, `getAchievements`, `setLeaderboardOptIn`, `getLeaderboard` | shell                                      | Progress derived from the member's own borrow history inside the window; completion auto-awards one badge + accessible text certificate; verified borrowing streak; leaderboard **off by default**, anonymous aliases, opt-in only.                   |
| **Scan & Borrow**       | `LibraryScanService` — `lookup`, `selfCheckout`, `returnItem`                                                                                           | `libraryScanner` (camera or typed barcode) | Returns only for the member's own active loan; unique scan key stored in the ledger so retries don't duplicate loans.                                                                                                                                 |
| **Digital member card** | `LibraryDigitalMemberCardService` — `issue`, `validate`                                                                                                 | `libraryDigitalMemberCard`                 | Opaque token valid **10 minutes**; only SHA-256 stored (`Operation__c='Member Card'`, Issued → Consumed); `validate` locks and consumes on first use; unknown/expired/replayed all return the same generic failure; returns display-safe fields only. |
| **Suggestions**         | `getSuggestedBooks` in `LibraryMemberSessionController`                                                                                                 | shell dashboard                            | Server-side suggestions from member history/interests.                                                                                                                                                                                                |

## Checklist for a new engagement feature

1. Resolve member from token. 2. Build idempotency key from member + target. 3. Store with `Operation__c`. 4. Return DTOs without internal Ids you don't need. 5. Add a Jest test for the UI and an Apex test for ownership isolation (Member A cannot see Member B).
