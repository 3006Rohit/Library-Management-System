# `scripts/` — automation

PowerShell (Windows, requires `sf` CLI) plus Apex scripts. Sub-folders: [`apex/`](apex/README.md) (ad-hoc/ops Apex) and [`seed/`](seed/README.md) (demo data).

| Script                            | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Example                                                             |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `deploy-library.ps1`              | **Release deploy.** Looks up the active `Library Member Notification Scheduler` job (cron `0 15 * * * ?`), refuses if ambiguous, temporarily unschedules it (`apex/unschedule-notification-scheduler.apex`), runs `sf project deploy start --manifest manifest/core-package.xml` (`--dry-run --test-level RunLocalTests` with `-ValidateOnly`), then restores the schedule in a `finally` block (`apex/restore-notification-scheduler.apex`). Reason: deploys fail while scheduled Apex is pending. | `.\scripts\deploy-library.ps1 -TargetOrg library-org -ValidateOnly` |
| `validate-deployment-package.ps1` | Offline gate: checks every `genAiFunctions` input/output JSON schema, authoring bundles, and manifest XML. With `-RunSalesforceValidation` also runs a check-only deploy.                                                                                                                                                                                                                                                                                                                           | `.\scripts\validate-deployment-package.ps1`                         |
| `validate-library-schema.ps1`     | Queries `Library_Schema_Diagnostic__c` and runs `apex/validate-library-schema.apex` to prove the runtime schema matches the code.                                                                                                                                                                                                                                                                                                                                                                   | `.\scripts\validate-library-schema.ps1 -TargetOrg library-org`      |
| `run-uat.ps1`                     | UAT gate: `npm test` → `npm run lint` → package validation → (unless `-SkipOrgTests`) Apex local tests → runtime schema validation. Stops at first failure.                                                                                                                                                                                                                                                                                                                                         | `.\scripts\run-uat.ps1 -TargetOrg library-org`                      |
| `import-library-workbook.ps1`     | Reads `data/Salesforce_Library_Demo_Data_100_Books.xlsx` through Excel COM (Windows + Excel needed), exports sheets to a temp folder (`.tmp-library-import`) and loads them with `sf data import bulk` / `sf data upsert bulk`.                                                                                                                                                                                                                                                                     | `.\scripts\import-library-workbook.ps1`                             |
| `retrieve-experience-site.ps1`    | Retrieves the Experience bundle and fails clearly if the org does not return deployable ExperienceBundle metadata.                                                                                                                                                                                                                                                                                                                                                                                  | `.\scripts\retrieve-experience-site.ps1 -SiteName Library`          |

## Typical flows

**Release:** `validate-deployment-package` → `deploy-library -ValidateOnly` → `deploy-library` → publish agents → publish site.
**New developer:** `npm install` → `sf org login web` → `run-uat -SkipOrgTests` → deploy → seed.

## Safety notes

- No script contains credentials. UAT-member scripts require a one-time password supplied at execution time.
- Always run `-ValidateOnly` first on production.
- If the process is killed during a deploy window, re-run `apex/restore-notification-scheduler.apex` (idempotent).
