# `lwc/` — Lightning Web Components

All UI is LWC. Components fall into four groups: **public/auth pages**, **member portal**, **librarian workspace**, and **shared building blocks**. Tests live in `<component>/__tests__/*.test.js` (27 Jest suites, run with `npm test`).

Component bundle = `name.html` + `name.js` + `name.css` + `name.js-meta.xml`. The `js-meta.xml` `targets` decide where a component can be placed (`lightningCommunity__Page` = Experience builder, `lightning__RecordPage`, `lightning__AppPage`, …). Components without targets are child components only.

> `jsconfig.json` is only for editor IntelliSense (ignored by deploy).

## Patterns used in the JS

- **Imperative Apex** (`import fn from '@salesforce/apex/Class.method'`) with a `try/catch` that shows a toast or inline error — no `@wire` for mutations.
- **Session token** is held client-side (member shell) and passed as the first argument to every `LibraryMemberSessionController` call; never shown to the user.
- **Accessibility:** member preferences set CSS classes on the shell (high contrast, larger text, reduced motion).
- **Idempotency keys** are generated in JS for scan operations to survive double-clicks.
